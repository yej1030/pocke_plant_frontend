# Pocket Plant 로컬 식물 건강 분석 재설계

2026-09-13 · 1단계 점검 완료, 데이터·학습 재설계 진행 전. 기존 학습안을 승인된 운영 모델로 간주하지 않는다.

## 앱에서 확인한 대상과 결함

- PlantRegister 기본 목록: 몬스테라, 스투키, 산세베리아, 스킨답서스, 필로덴드론, 페퍼로미아, 칼랑코에, 아레카야자, 관음죽, 싱고니움 등. 사용자 추가 대상: 토마토 등 작은 텃밭 작물.
- DiseasePredict는 이미지 하나만 전송한다. 식물 종류와 관찰 메모는 추론에 들어가지 않는다. 센서 데이터도 이 경로에 연결되지 않았다.
- DiseaseResult가 모델 confidence를 실제 질병일 확률로 표현하고 정상/판단불가에도 '감지된 이상 징후'를 붙였다. 1단계에서 숫자 확률·막대를 제거하고 참고 결과와 기록용 메모로 정정했다.
- ai_server의 5분류는 병원체, 시각 증상, 입력 거부를 섞는다. yellowing_virus는 황변 원인을 바이러스로 오인하게 한다.
- prepare_dataset.py는 알 수 없는 라벨도 leaf_spot_blight로 넣는다. PlantDoc의 '... leaf' 같은 정상 라벨도 healthy 문자열이 없어 오분류될 수 있다. 출처별 명시적 라벨 표가 필요하다.
- PlantVillage와 PlantDoc train/test를 합쳐 다시 나누면 독립 현장 평가가 사라진다. 파일 해시만으로 같은 식물의 다른 사진·리사이즈·연속 촬영 중복은 막지 못한다.
- CIFAR의 저해상도 이미지를 확대하는 것만으로 실제 책상·화분·손·조화·비식물 사진 거부를 검증할 수 없다.
- train.py는 평가 때 gradient를 끄지 않고, best 가중치를 메모리에만 보관하여 Colab 중단 시 잃는다. calibration은 center crop, 서비스는 10-view TTA라 평가와 배포가 다르다. 단위 테스트 통과는 인식 성능의 증거가 아니다.

## 지원 범위

| 대상 | 제공할 결과 | 필요한 근거 |
| --- | --- | --- |
| 실내·관상식물 | 뚜렷한 이상 없음 / 황변 / 잎끝·가장자리 갈변 / 반점·괴사 / 가루·부착물 / 손상 등 관찰 증상 | 해당 식물과 실내 촬영 조건에서 검증한 증상 라벨 데이터 |
| 토마토 | 검증된 토마토 병해·해충 후보와 추가 관찰 안내 | 토마토 원본 라벨, 실제 텃밭 사진의 독립 시험 |
| 다른 텃밭 작물 | 작물별 검증 완료 후 순차 지원 | 작물별 데이터와 별도 성능 |
| 흐림·멀리 찍음·비식물·미지원 | 재촬영 / 분석 범위 밖 / 판단 어려움 | 품질 불량·미지원·비식물 시험셋 |

실내 증상은 동시에 나타날 수 있으므로 다중 라벨을 검토한다. 황변을 과습·영양 결핍·바이러스 중 하나로 강제 분류하지 않는다. 무늬종의 정상 무늬, 몬스테라의 정상 구멍, 자연 노화도 별도로 검증한다. 잎 사진으로 뿌리 썩음이나 토양 원인을 확진하지 않는다.

식물 종은 등록 정보를 받아 사용자가 확인한다. 종 정보만으로 사진 자체가 해당 종이라고 단정하지 않는다. 규칙 기반 관리 질문은 관찰 결과와 구분하고 질문을 근거로 확률을 만들어내지 않는다.

## 단계별 실행 및 통과 조건

1. **점검/표현 정정 (완료)**: 앱·서버 경로와 라벨 결함 기록, 확률 오표현 제거. 새 모델 학습·교체는 미완료.
2. **데이터 계약 (다음)**: 출처, 사용권, species, 원본 label, symptom label, plant/session group, split, 라벨 검토 상태를 manifest로 관리. 미지 라벨은 실패 처리. 원래 독립 test는 유지하고 근접 중복과 식물/촬영 그룹 단위 누출을 검사한다. 실내식물 데이터 부족을 토마토 사진으로 채우지 않는다.
3. **재현 가능한 학습**: 토마토 제한 범위 baseline부터 구축. 실내 증상 모델은 검토한 실내 데이터가 준비되면 별도 학습. 사전학습 특징을 이용한 로컬 전이학습, 재개 가능한 epoch checkpoint, 고정 설정·seed, 로그와 데이터 버전 저장. 평가와 서비스 전처리 일치.
4. **검증**: 같은 시험 이미지로 기존/신규 비교. 작물·증상·촬영 환경별 precision/recall/F1, 혼동행렬, 거부 후 정확도와 수용률, 정상 무늬 오탐, 미지원 오수용, 로컬 CPU 지연·메모리 측정. 임계값은 validation으로 정하고 test를 보고 튜닝하지 않는다. 실내/텃밭 시험 결과를 합친 평균 하나로 출시하지 않는다.
5. **연결/출시**: frontend → Spring → ai_server로 species와 필요한 관찰 항목 전달, DTO 확장. status(관찰 결과/재촬영/미지원/판단불가), 관찰 증상, 가능한 원인, 다음 확인 항목을 분리. 검증한 모델만 명시적으로 활성화하며 무통보 legacy fallback을 없앤다. 모델·데이터 버전과 지원 범위를 health에 노출한다.

## 현재 남은 입력과 자료

실내식물 병해·환경 스트레스에 대해 검토된 학습 사진과 독립 시험 사진이 확인되지 않았다. 현재 가중치의 학습 출처·라벨 순서·기존 현장 지표도 확인이 필요하다. 이 근거 없이 '성능 개선 완료' 또는 '실내식물 지원 완료'로 표시하지 않는다. 다음 단계에서 공개 자료의 식물별 포함 범위와 사용권을 조사하고 부족분 수집/라벨링 표를 만든다.
